# PDF View With Findings On The Page — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "PDF" tab in the LV workspace that shows the original PDF pages with every finding marked on its
quoted evidence and a note in the margin, linked both ways to the selected item.

**Architecture:** The server locates each finding on the page with PyMuPDF (search restricted to the item's own
stretch of the document) and returns rectangles in PDF points. The browser draws the pages with pdf.js (canvas
plus text layer), lays the rectangles over them and lists notes in a margin column. Read-only; user notes are a
later step.

**Tech Stack:** Python 3.12, FastAPI, PyMuPDF (already a dependency); React 19, Vite 8, `pdfjs-dist` (new).

**Spec:** `docs/superpowers/specs/2026-11-21-pdf-view-design.md`

## Global Constraints

- Coordinates everywhere: PDF points, origin top-left, as PyMuPDF gives them. Pages are numbered from 1.
- A mark never sits outside the stretch of the item it belongs to. Quote not found there → the item's number
  line; no item → `located: "none"`, no rectangles.
- LV text is never translated or re-typeset; the page is the client's page.
- `dataset/` is read-only. No new Python dependency.
- `uv run python scripts/eval_pdf_parser.py -v` must print the same scores before and after Task 1.
- Before writing pdf.js code, read the current `pdfjs-dist` docs (context7) for the worker setup and the
  `TextLayer` API; do not rely on memory.
- UI text English, Stop / Caution / Note colours and the yellow-and-white language from `web/src/styles.css`.
- Commit at the end of a task only if Utku has agreed to commits for this work; otherwise leave the changes in
  the working tree and skip the commit step.

## Review Focus

1. The same phrase stands in two items (e.g. "nach Wahl des AG"): the mark for a finding on the second item
   must be in the second item, not on the first hit of the page. → Task 2 test.
2. A quote broken over a line end, with or without a hyphen ("Stahlum-/mantelung"): still found as a quote.
   → Task 2 test.
3. An item whose text continues on the next page: a quote on the continuation page is found and reported with
   that page. → Task 2 test.
4. A finding added by the AI review after the marks were loaded: the PDF tab shows it without a reload of the
   page. → Task 4 step 6.
5. An analysis without a kept PDF (GAEB, Excel, temporary upload): no PDF tab, and both endpoints answer 404
   with a readable message, not 500. → Task 3 test.

### Task 2: Locate findings on the page

**Files:**
- Create: `src/boq/pdfmarks.py`
- Test: `tests/test_pdfmarks.py`

**Interfaces:**
- Consumes: `SourceRef.page`, `SourceRef.y` (Task 1); `Finding.item_oz`, `Finding.evidence`.
- Produces:

```python
def locate(pdf_path: str | Path, boq: BoQ, findings: list[Finding]) -> dict:
    """{"pages": [{"width": float, "height": float}, …],          # one per page, in order
        "marks": [{"finding": int,                                 # index into `findings`
                   "oz": str | None, "page": int | None,           # page of the first rectangle
                   "rects": [[x0, y0, x1, y1], …],                 # all on `page`
                   "located": "quote" | "item" | "none"}, …]}      # one per finding, same order
    """
```

Rules the tests do not fully determine:

- An item's stretch starts 8 pt above its number line and ends at the next item's number line (next in
  document order), crossing page breaks; the last item's stretch ends at the end of the document.
- Search with `page.search_for(text, clip=…)` page by page through the stretch; PyMuPDF matches across line
  breaks and joins line-end hyphens by default. Order of attempts: the whole evidence; then, if the evidence
  contains "…" or "...", each part of at least 12 characters (first part found wins); then give up on the quote.
- If the quote is not in the item's stretch, search the pages before the first item's number line (the
  preliminary remarks). A hit there is `located: "quote"`.
- `located: "item"`: one rectangle, the union of the words on the item's number line (words whose vertical
  centre is within 3 pt of `SourceRef.y`).
- A quote found on several pages reports the first page and only that page's rectangles.
- `item_oz` missing or not in `boq`, or the item has no `page`: remarks search, else `"none"`.

- [ ] **Step 1: Write the failing tests** in `tests/test_pdfmarks.py`. A helper builds a PDF in `tmp_path` with
  `pymupdf` (`page.insert_text`) and parses it with `parse_file`, so the tests do not depend on a finding the
  checks happen to produce. Layout of the helper PDF: a column header line the parser accepts (copy the header
  wording from a dataset PDF the parser tests already use), then items `1.1.10`, `1.1.20` on page 1 and
  `1.1.30` starting at the foot of page 1 with its description continuing on page 2.

```python
def finding(oz, evidence):
    return Finding(item_oz=oz, category="contract_risk", check_id="T", severity="warn",
                   evidence=evidence, explanation="x", action="ask_client")

def test_same_phrase_in_two_items_marks_the_right_one(two_page_lv):
    path, boq = two_page_lv            # 1.1.10 and 1.1.20 both contain "nach Wahl des AG"
    m = locate(path, boq, [finding("1.1.20", "nach Wahl des AG")])["marks"][0]
    second = next(i for i in boq.items if i.oz == "1.1.20").source
    assert m["located"] == "quote" and m["page"] == second.page
    assert all(r[1] >= second.y - 8 for r in m["rects"])

def test_quote_broken_at_a_line_end_is_found(two_page_lv):
    path, boq = two_page_lv            # 1.1.10 prints "bauseitige Stahlum-" / "mantelung"
    m = locate(path, boq, [finding("1.1.10", "bauseitige Stahlummantelung")])["marks"][0]
    assert m["located"] == "quote" and len(m["rects"]) >= 2

def test_quote_on_the_continuation_page(two_page_lv):
    path, boq = two_page_lv            # 1.1.30 continues on page 2 with "einschl. aller Nebenleistungen"
    m = locate(path, boq, [finding("1.1.30", "einschl. aller Nebenleistungen")])["marks"][0]
    assert m["located"] == "quote" and m["page"] == 2

def test_quote_not_in_the_item_falls_back_to_the_item_line(two_page_lv):
    path, boq = two_page_lv
    m = locate(path, boq, [finding("1.1.10", "this text is nowhere")])["marks"][0]
    first = boq.items[0].source
    assert m["located"] == "item" and m["page"] == first.page and len(m["rects"]) == 1
    assert m["rects"][0][1] <= first.y <= m["rects"][0][3]

def test_finding_without_a_place(two_page_lv):
    path, boq = two_page_lv
    marks = locate(path, boq, [finding(None, "nowhere"), finding("9.9.9", "nowhere")])["marks"]
    assert [m["located"] for m in marks] == ["none", "none"] and all(m["rects"] == [] for m in marks)

def test_project_c_every_item_finding_is_placed():
    boq = parse_file(str(PROJECT_C))
    findings = run_checks(boq)
    out = locate(PROJECT_C, boq, findings)
    assert len(out["marks"]) == len(findings) and len(out["pages"]) == pymupdf.open(PROJECT_C).page_count
    for f, m in zip(findings, out["marks"]):
        if f.item_oz:
            assert m["located"] in ("quote", "item") and m["rects"]
            page = out["pages"][m["page"] - 1]
            assert all(0 <= r[0] < r[2] <= page["width"] and 0 <= r[1] < r[3] <= page["height"] for r in m["rects"])
    by_quote = sum(m["located"] == "quote" for m in out["marks"])
    print(f"project C: {by_quote} of {len(findings)} findings located by quote")
    assert by_quote > 0
```

`PROJECT_C = dataset/04_pdf_tiefbau_sonstige/Leistungsverzeichnis.pdf`.

**Interfaces:**
- Consumes: `Analysis.pdf`, `loadMarks`, `sourcePdfUrl`, `PdfMarks` (Task 3).
- Produces: `PdfView({ analysis, selectedOz, onSelect }: { analysis: Analysis; selectedOz: string | null;
  onSelect: (oz: string) => void })`.

- [ ] **Step 1: Install and wire pdf.js.** `cd web && npm install pdfjs-dist`. Worker through Vite's `?url`
  import, set once at module load in `PdfView.tsx`. Confirm against the current docs.

- [ ] **Step 2: Pages.** One placeholder per page sized from `PdfMarks.pages` (so the scrollbar is right before
  anything is drawn), scaled to the width of the page column. A page is rendered (canvas at
  `devicePixelRatio`, plus the pdf.js text layer so text can be selected) when it comes within one screen of the
  viewport (`IntersectionObserver`), and its canvas is released when it is more than three screens away.

- [ ] **Step 3: Marks.** A layer over each page with one box per rectangle, positioned by
  `rect × (rendered width / page width)`, in the severity colour of its finding at low opacity so the text stays
  readable; `located: "item"` marks are drawn as a bar in the left margin of the line instead of a highlight
  over it. The mark layer must not swallow text selection (pointer events only on a click, not on drag).

- [ ] **Step 4: Notes.** A margin column right of the pages. Per page, one note per finding on that page
  (severity word, item number, `Finding.title`, falling back to the start of `explanation`), placed at the top
  of its first rectangle and pushed down where it would overlap the note above. Findings with
  `located: "none"` are listed above the first page under "Not tied to a place in the PDF". Hovering a note
  emphasises its marks and the reverse.

- [ ] **Step 5: Link with the workspace.** In `App.tsx`: `View` gains `"pdf"`, tab label "PDF", offered only
  when `analysis.pdf`; `&view=pdf` accepted in the deep link. Clicking a note or mark calls `onSelect(oz)` —
  the same handler the findings list uses, so the item sheet opens. When `selectedOz` changes from outside,
  scroll its first mark into view (fall back to `item.source.page` / `y` for an item without findings).

- [ ] **Step 6: AI review.** Marks are reloaded when `analysis.findings.length` changes, so findings added by
  "Run AI review" appear in the PDF tab (Review Focus 4).
